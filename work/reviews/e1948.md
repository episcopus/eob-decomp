## Findings

- [ ] must-fix src/E1948.ASM:7-8: the header cites "whitepaper 2.7" for the speaker and Tandy driver select. WHITEPAPER.md section 2.7 (line 127) covers keyboard, mouse, AdLib and the saved game; it says nothing about the PC speaker or the Tandy driver, and 2.6 only gives the argv sound digit. The evidence for the claim is the code: E07C8.C:302-308 (install and select) and E177D.C:161-186 (PlaySound starts through StartSound). Cite that code, and add the driver to the whitepaper (the playbook asks for the whitepaper to be extended) or drop the citation.
- [ ] must-fix src/E1948.ASM:47 (gSpeakerOn; also E07C8.C:31 "1 while the speaker is on"): the name says the PC speaker is on when the value is 1, but 1 is the Tandy path. Every test in this file takes 1 as Tandy (lines 186, 280, 393, 420, 446, 548, 588), and E177D.C:59-60 agrees. The name contradicts the value. Give it a name for the Tandy select (for example gTandyOn, 1 Tandy, 0 PC speaker) with `make rename`, so E177D.C and E07C8.C follow on merge.
- [ ] must-fix src/E1948.ASM:40 and 389-390 (gVoiceTandyVol and the _VoiceOn comment): "Tandy attenuation nibble" and "stored attenuation, inverted" name the wrong value. _VoiceOn writes the stored nibble XOR 0Fh to the SN76489 attenuation latch (lines 401-402), and _VoiceOff writes 0Fh for silence (line 428). So the stored nibble is a volume (0 silent, 15 loudest), and the chip receives its inverse. That the chip takes 0 as loudest and 15 as off is datasheet knowledge [H], consistent with the code.
- [ ] must-fix src/E1948.ASM:37 (gVoiceActive): "1 while a note is sounding" is backwards. 1 means the voice reads its next note or command on this tick (lines 167-169; set to 1 at 123 and at 347 when a note's duration runs out). 0 means a note is sounding and its duration counts down (set to 0 at 212 after a note starts, counted at 343-344).
- [ ] must-fix src/E1948.ASM:36 (gVoiceRestart): "1 = re-issue the note" does not match the code. Nothing in this unit sets it to 1; its only writes are 0 (lines 124 and 352). When it is 1, the check at 349-350 falls through to muteVoice (348-353), which silences the voice. Say that, and say the writer is unknown (no writer in this unit).
- [ ] must-fix src/E1948.ASM:48 (gTickCount): "reloads gTickPhase" is wrong. The count does not reload the phase. When it passes 123h it wraps to 0 (lines 69-71, 80-81), and only then gTickPhase is incremented, wrapping at 3Bh (lines 72-79). The count period is 292 ticks, which at the 291 Hz rate the install programs (1193180 / 4096, see the PIT finding below) is about one second [H], so gTickPhase counts seconds up to 60 [H]. Say what the period is, and mark the seconds reading [H] until the oracle confirms it.
- [ ] must-fix src/E1948.ASM:105 (_SoundTick header): "rest (E6h)" is wrong. E6h reads a frequency word and divides the PIT clock (34DCh with 12h, 1193180) or the Tandy clock (0B4F4h with 1, 111860) by it (lines 282-289), then plays the result with the length byte that follows (lines 294-296, noteDone at 203-205). It is a note at an explicit frequency. A rest is a table value of 0 (lines 195-196, 200-201). Replace "rest (E6h)" with "a note at an explicit frequency (E6h)".
- [ ] must-fix src/E1948.ASM:509-510 (install comment): "programs PIT channel 2 (mode B6h) with divisor 1000h" is wrong. Lines 536-541 write 36h to port 43h (channel 0, mode 3), then the divisor 1000h to port 40h (channel 0). Only after that does 0B6h go to port 43h (channel 2, mode 3, no count loaded, lines 542-543). So channel 0 is set to 1000h (about 291 Hz, the rate the handler's 123h count assumes, line 70), and channel 2 gets only its mode; _SetVoicePitch loads its count (lines 448-450, port 42h). Fix the comment.
- [ ] must-fix src/E1948.ASM:562-564 (uninstall comment): "programs PIT channel 2 with divisor 0" is wrong. Lines 581-586 write 36h to port 43h and the divisor 0 to port 40h, so channel 0 goes back to its BIOS divisor 0 (65536, about 18.2 Hz). Fix the comment.
- [ ] must-fix src/E1948.ASM:511 (install comment): "Called by main (07C8:0557, 055E)" names the wrong caller. Both call sites are in StartupGame: E07C8.C:302 and 305, inside the function that starts at 07C8:0199 (E07C8.C:172). 07C8:0557 and 055E lie between 07C8:0199 and ShutdownGame at 07C8:058A (E07C8.C:318), so they are in StartupGame, not main. The packet agrees (07C8:0199 StartupGame). Name StartupGame.

- [ ] should src/E1948.ASM:647: "the PC speaker gate bit gSpeakerOn" misnames the flag. The PIT gate is port 61h bit 0 (lines 395-397); gSpeakerOn selects the driver (1 Tandy). Say "the driver select gSpeakerOn" (this changes with the gSpeakerOn rename above).

- [ ] should QUIRK marks (READABILITY.md, "Quirks"). These behaviours look wrong and must be kept, so each needs a `QUIRK <address>:` comment: (a) lines 315-318: the clamp to 1 never runs. `sub` sets ZF only for a zero result, and a zero result cannot overflow, so the `jne` at 317 always jumps and a zero amplitude is kept. (b) lines 328-330: E9h saturates to 0FFh only on signed overflow, so 100 plus 100 becomes 255 but 200 plus 100 wraps to 44. (c) lines 205-206: `inc al` on a duration byte of 0FFh wraps to 0, so that note lasts amp minus 1 ticks, not 256 times amp minus 1. (d) lines 282-289: `div` raises INT 0 when the quotient exceeds 0FFFFh, which is a frequency word of 18 or less on the PC path (1193180 / 18 = 66287) and 1 on the Tandy path (111860). Mark (d) as [H] unless the oracle confirms it.

## Summary

The unit is understandable from its source alone once the comments are corrected: its functions, globals and call graph are clear, and the matcher proves the bytes. As written, it is not: eleven must-fix items. Six comments describe the code wrongly (the PIT channels at install and uninstall, the E6h "rest", gVoiceActive, gVoiceRestart, gTickCount, and the Tandy volume nibble). Two comments name the wrong caller (StartupGame, not main). One name (gSpeakerOn) says the opposite of its value (1 is Tandy), and one citation (whitepaper 2.7) does not hold. Names that remain weakly backed: _SoundDriverPause (the only caller tears the driver down right after it), and gSpeakerOn, which is only a rename away. No placeholder name needs "Purpose unknown" beyond what is already in the comments, and no matcher or spec question arose, so there is no escalation.
