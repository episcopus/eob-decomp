- [ ] must-fix src/E1A29.C:52-57 (the header of f1A29_000F): "The one caller found, 1BBE:01F4, passes the mouse pointer shape record ... as `src` with the pointer's coordinates". Wrong on two counts. (a) 1BBE:01F4 does not call this front end: it is `lcall [0x80c2]` inside ShowPointer (1BBE:00ED; disasm of eob/EOB.EXE 1BBE:01F0 `mov ax, 0`, 01F3 `push ax`, 01F4 `lcall [0x80c2]`; src/E1BBE.ASM:252-258 `call dword ptr [gDraw80C2]`). It calls the driver pointer directly, so it passes the unclipped absolute position gShapeX/gShapeY and no region origin, which this front end would add. (b) f1A29_000F is not called from one site: the packet's "called by" column lists 20 call sites (082C:063B, 0D1C:070F, 0EF3:05BD, 0EF3:06E7, 1547:0544, 1547:0642, 1547:07E7, 1547:0991, 16A5:07C3 and 11 in ovl0 to ovl5); 082C:0675 `lcall 1A29:000F` confirmed by disasm. Fix: state that the mouse pointer bypasses this front end (ShowPointer calls ds:80C2 itself, with gShapeX/gShapeY), and drop "the one caller found".

## Summary

The unit is understandable from its source alone, and the names hold: the region record, the four globals, SelectRegion and the setter's argument order all check out against the bytes. Two claims are wrong and block the pass: the header of f1A29_000F says 1BBE:01F4 is "the one caller", but that instruction calls the driver pointer directly inside ShowPointer, and the front end has 20 callers; and the rename note for gRegionBottom says "first argument" where the bottom edge is the fourth. The shoulds are a pointer-caller claim that is true for ds:80C2 only, incomplete reader lists, and a pixel-versus-line wording. Function names stay placeholders (`f1A29_xxxx`) and that is fine: `Purpose unknown` is still true for the front ends' roles, and the `extra` of 1A29:0107 and 1A29:0148 has no caller to show what it means. The name `g811F` in src/E07A9.C is a cross-unit question for that unit's review, not a finding here.
