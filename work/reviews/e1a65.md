## Findings

Each finding is a checkbox. `must-fix` blocks `make review-pass` until a decompiler ticks it off
(with the commit that fixes it); `should` and `note` do not block.

- [ ] should src/E1A65.C:1-2,22: "vertical retrace bit" and the name CalibrateRetrace rest on the usual meaning of port 3DAh bit 3, not on bytes in this unit. The unit only proves: wait for the tick counter, wait 4 more ticks, call 1DE4:0000 10000 times (cmp 0x2710 at 1A65:00BB), count nonzero results (`inc [bp-0xc]`, 1A65:00B0) against zero results (`inc [bp-0xa]`, 1A65:00B5), and set ds:FE6C to 1 if nonzero won (1A65:00C8..00CA, `jle`). Tag the retrace meaning [H] (as work/reviews/e1de4.md already asked for E1DE4.ASM). The name is a placeholder, which is fine; say so once the tag is there.
- [ ] should src/E1A65.C:2-7: the header says what the function does but not why it is a polarity test. Over about 10000 reads taken right after a tick edge the bit is either mostly set or mostly clear, and gFE6C records which. The only reader of ds:FE6C in the resident code is 1A16:0010 (E1A16.C WaitFrames), which pushes it as the mode argument of 1DE4:000D; that mode selects the wait order (see E1DE4.ASM). Say "polarity" and name that link; "measure" suggests a rate.
- [ ] should src/E1A65.C:7-8: the last sentence ("the two chained assignments are what the compiler needs to merge the two zero stores into one xor ax,ax") is unclear. There are two chains: `i = gFE6C = 0` (one `xor ax,ax` at 1A65:0020, stored to ds:FE6C at :0022 and moved to DI at :0025) and `clear = set = 0` (`xor ax,ax` at :0098, two stores at :009A and :009D). Say that, or drop it; it also belongs next to the statements, not in the header.
- [ ] should src/E1A65.C:20,35-38: `i` is a register counter that is incremented once per outer iteration of the 4-tick wait (1A65:0077 `inc di`) and never read afterwards. It exists only because the original has it (DI is pushed at :0015 and `i` is the first register variable). A one-line comment ("dead counter kept for the bytes") would stop the next reader from deleting it. `k` (SI, 200 iterations, 1A65:0078..0080) is a pure delay loop; the same applies.
- [ ] note Checked against the disassembly: the far pointer at [bp-4] is 0000:046C (1A65:0016..001B). The two timer reads are 32-bit (`es:[bx]` low, `es:[bx+2]` high) and done under cli (1A72:02FC is `cli; retf`) with sti (1A72:02FA is `sti; retf`) afterwards, as the file says. Between the first wait loop and the deadline read there is an extra cli/sti pair (1A65:0055 and :0070). The comment "about 220 ms" is 4 ticks at 18.2 Hz (54.9 ms each); the real wait is at least 3 and up to 4 ticks, since the deadline is taken right after the edge, so it is nearly 4. Fine.
- [ ] note The 4-tick wait compares an unsigned 32-bit tick count against `ticks + 4`. If the BIOS counter rolls over at midnight (0x1800B0 to 0) during this window, `*timer < deadline` stays true until the counter reaches the old deadline again, which is a day. That is the original's behaviour (the code at :0082..:0096 is the same), not something to fix; a practical risk only on a machine started within about 220 ms of midnight.
- [ ] note Both timer waits have no timeout. If the tick counter does not advance (no timer interrupt) the first loop at :0041..:0053 hangs; original behaviour.
- [ ] note Call sites: the single caller is `lcall 1A65:000E` at 07C8:04E9 inside the function at 07C8:0199 (the packet lists it as 07C8:0199, the function start), right after `mov byte ptr [0x3056],1` and a call to 1C0E:13E7. That is startup code, so gFE6C is set once at run time before any WaitFrames. Overlay code was not scanned for other accesses to ds:FE6C; in the resident segments only 1A16:0010 (read) and 1A65:0022, :00CA (writes) touch it.
- [ ] note Types: `int` for gFE6C is consistent with E1A16.C (`extern int gFE6C`). In practice it holds 0 or 1; 1DE4:000D only compares its low byte with 1 (see work/reviews/e1de4.md). `clear` and `set` are plain ints compared signed (`jle`, 1A65:00C8), matching `int`. `deadline` as `unsigned long` is supported by the unsigned compares (`jb` at :008F and :0096). `timer` as `unsigned long far *` is supported by the two-word reads.
- [ ] note Extern names f1A72_02FC, f1A72_02FA, f1DE4_0000 are address placeholders. f1A72_02FA/02FC are exactly sti/cli far stubs (one instruction and `retf`); better names (EnableInterrupts, DisableInterrupts) are justified by those bytes and should be shared with whichever unit lifts 1A72 (unit e1a72), not invented here. They are only declared in this file for now (grep in src/: no other use).

## Summary

The unit is one 200-byte function and is understandable from its source alone; the code is accurately described. No claim in it is contradicted by the disassembly. The weak points are wording: the retrace meaning of port 3DAh bit 3 is prior knowledge, not evidence in these bytes (tag it [H]); "measure" should say polarity test; the explanation of the chained assignments is unclear; and the dead counter `i` deserves a comment. The names are placeholders and the types match the instruction forms. No must-fix.
