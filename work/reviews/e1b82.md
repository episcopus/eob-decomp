## Findings

Each finding is a checkbox. `must-fix` blocks `make review-pass` until a decompiler ticks it off
(with the commit that fixes it); `should` and `note` do not block.

- [x] must-fix src/E1B82.C:18: "(19BC:0059)" is the wrong address. 19BC:0059 is `je 0x31`, the end of
  the retry test in the loop (19BC:0057 to 0059). The code for `MK_FP(FP_SEG(blk) + 1, 0)`
  (E19BC.C:59) is at 19BC:00B3 (`inc ax`) and 19BC:00B4 (`mov [bp-4], 0`). Cite 19BC:00B3.
  Fixed in b7d643e: the union comment now cites "the `inc ax; mov [bp-4],0` at 19BC:00B3".
- [x] must-fix src/E1B82.C:81-83: "the case bodies are laid out in source order 0, 3, 1, 2, 4, the
  order of the table at cs:020d" is wrong. The table at cs:020D is indexed by format value and lists
  the cases 0, 1, 2, 3, 4 (00E7, 011E, 0176, 010D, 01CC). The bodies are in the code in the order
  1B82:00E7 (0), 010D (3), 011E (1), 0176 (2), 01CC (4). Say that: the bodies follow the source order
  0, 3, 1, 2, 4 (1B82:00E7, 010D, 011E, 0176, 01CC), and the table is indexed by value.
  Fixed in b7d643e: the Unpack comment now says the bodies follow source order 0, 3, 1, 2, 4
  (1B82:00E7, 010D, 011E, 0176, 01CC) and the table at cs:020D is indexed by format value.
- [x] should src/E1B82.C:81-82: "the original keeps the cbw;cwd; C++ codegen does that here, the C front
  end folds (int)(long)*src to *src" is hard to parse. Suggest: "The original sign-extends the format

## Summary

The unit reads well from its source: the names of the four functions, the globals gBufSeg and gBufSize,
the callees (FileOpen, MemAlloc, f19EC_0002, Unpack0 to Unpack4) and the parameter names all agree with
the bytes and with the other files of `src/`. Two comments say something the bytes do not show: the
address of the flag 0x20 allocation (19BC:0059 should be 19BC:00B3) and the order of the switch table
(it is indexed by format, not in source order). Those are the must-fix items. Also: `n` in LoadPacked is
a length, not a counter, and the case 4 comments mix block offsets with the advanced local `src`. The
format-numbered names Unpack1..Unpack4 are placeholders by design (the 1D9A unit takes them from
their callers).

What I checked (read-only; no source edited):

- `make match FILE=src/E1B82.C`: 4 of 4. `make readability UNIT=e1b82`: 0 findings.
- The WorkBuffer comment (lines 15 to 19): 1B82:013F and 1B82:0197 are `push word ptr [bp - 2]`
  (disassembled with `tools/re/disasm.py`), and 19BC:00B3 is the `inc ax` of the flag 0x20 branch.
- LoadFile (1B82:0009): `mov ax, 1; push ax` is the mode argument of the FileOpen call (1B82:000D to
  0010), so mode 1 is the literal in the bytes. The handle is kept in SI (1B82:001F `mov si, ax`) and
  goes straight to FileRead with no compare.
- Unpack (1B82:00C7): the format byte is read at 00D1 and sign-extended (00D4 and 00D5), and the
  range test is `cmp bx, 4` at 00D8, followed by the table jump. The C has no default branch.
- The palette field (line 119): all 131 format-4 entries of the PAK archives (EOBDATA1 14, 2 1,
  3 29, 4 30, 5 25, 6 32) have the u16 at block offset +6 equal to 0 (`tools/re/pak.py` read_pak,
  checked on this commit). Other files were not checked for format-4 blocks.
- Callees and globals: FileOpen, FileRead, FileClose (E082C.C:66-68, E177D.C:27-29, EOV2.C:199-201),
  MemAlloc and MemFree (E07A9.C:71, E1A47.C:22-23), f19EC_0002 (E19EC.C:18-20, which returns
  MK_FP(gSegsFC0C[kind | 1], 0)), Unpack0 (E1BA8.ASM:16, which copies CX bytes), Unpack1..4 (E1D9A.ASM
  Unpack4 at 0013 takes its arguments at bp+6 to bp+0Eh), gBufSeg and gBufSize (re/globals.toml:270-277).
- LoadPacked's segment arguments (E082C.C:275, E1B82.C:54-56) and the names srcKind and dstKind.

## Findings

- [ ] must-fix src/E1B82.C:119: "0 in every pinned file" claims more than the check. The check covers the
  131 format-4 entries of EOBDATA1 to EOBDATA6.PAK (the u16 at block offset +6 is 0 in all 131). No other
  pinned file was checked for format-4 blocks. Say "0 in all 131 format-4 entries of the PAK files", or
  check the other files first.
- [ ] should src/E1B82.C:74: "Unpack0 copies the long count at block offset +2" names the value wrongly. The
  long at block offset +2 is the 32-bit unpacked size (WHITEPAPER 4.2, and 1B82:00C7 reads it as
  `*(long far *)(src + 2)`), passed as Unpack0's `len`. Say "passes the 32-bit unpacked size at block offset
  +2 as its length, and Unpack0 copies that many bytes from block offset +8".
- [ ] should src/E1B82.C:54: "takes the source and destination segments" for f19EC_0002's result. The function
  returns far pointers with offset 0 (E19EC.C:18-20). Say "far pointers at offset 0 (segments)".
- [ ] should src/E1B82.C:90 and :116 to :121: `n` is the number of bytes Unpack skips after the header
  (`src += n`), not a counter. READABILITY reserves `n` for counters, and in this file LoadPacked's length is
  already `packedLen`. Name the role, for example `skipLen`, and keep the palette claim and its source
  (WHITEPAPER 147) in the comment at line 119. The name then claims only what the code does, which
  matters because the palette meaning is not shown by any pinned file (the field is 0 in all of them).
- [ ] should src/E1B82.C:44 to :51: the unchecked FileOpen result is a quirk a port must keep, and it is not
  marked. Mark it `QUIRK 1B82:0009:` in LoadFile (the handle is kept in SI at 1B82:001F and goes to FileRead
  with no test), and say the same of LoadPacked (1B82:0041), whose matched C also has no test between
  FileOpen and FileRead.
- [ ] should src/E1B82.C:92 to :124: the switch has no default, so a format byte outside 0 to 4 leaves dst
  untouched. The bytes test the format with `cmp bx, 4` at 1B82:00D8 and an unsigned jump, so a format above
  4, including the negative values 0x80 to 0xFF, skips the switch. Mark it `QUIRK 1B82:00C7:` with that.
- [ ] note src/E1B82.C:100, :101, :108, :109, :119: the flag 0x20 and the sizes 0x3C00 and 0xFC00 are bare
  literals here, and the same flag is bare in E07C8.C:211 to :247 and E07A9.C:112, while E19BC.C:56 tests
  `flags & 0x20`. The meaning of 0x20 is explained only in the WorkBuffer comment. No shared name exists yet,
  so this is for phase 6 naming, not a change to this unit.
- [ ] note src/E1B82.C:44, :49, :66: "mode 1" stays a bare number, as in round 2. The other units also pass a bare
  1 (E082C.C:474, E177D.C:48, EOV2.C:224, EOV2.C:295), so the constant belongs with 1C0E.

## Summary

The unit reads well and its names match the bytes and the other files. The palette claim on line 119 is the
one must-fix: it states a scope the check did not cover. The comments on `Unpack` and `LoadPacked` are
otherwise accurate: the addresses I checked (1B82:013F, 1B82:0197, the mode-1 push at 1B82:0010, the
sign extension at 1B82:00D1 and 00D4, and the range test at 1B82:00D8) are where the comments say. The
should items are a clearer name for `n`, two behaviours a port must keep that are not marked as quirks,
and one wording fix in the `Unpack0` comment. The 0x20 flag and the buffer sizes are for phase 6 naming.
