- [ ] must-fix src/E19F3.C:11-14: "E1DE7.C:245 to :248 pass gTextLeft, gTextTop and gTextWidth unshifted to ClipRect" is wrong in two places. Only line 245 calls ClipRect; lines 246 to 248 are the gFillRect and gDrawText calls. At 245 the y1 argument is `gTextTop + gFontHeight1A47` (one line down), so gTextTop is unshifted only as y2, and gTextTop is a row, not a column, so it does not support the columns reading that sentence is for. Fix: cite E1DE7.C:245 alone; say gTextLeft (x1 and x2) and gTextWidth are passed unshifted, y2 is gTextTop unshifted, y1 is gTextTop plus one line, and the height is `line` (E1DE7.C:244). Evidence: src/E1DE7.C:244 to :249.
- [ ] must-fix src/E19F3.C:32-33: "whose far edge x2 + width = 20 is inside the screen" uses a different far edge from the one the header defines. Lines 4 to 6, 18 and 40 to 41 define the far edge as x1 + width, which the shifts keep fixed. In that example x1 is 0 after the shift and width is -10, so the far edge the header defines is x1 + width = -10, below column 0. Fix: give the far edge as x1 + width = -10 and say that the negative width reaches the far routine; if x2 + width is mentioned at all, call it the second origin's extent, not the far edge. Evidence: the example's arithmetic follows from 19F3:0030 to 0039 with x1 = -30 and width = 20 (x2 = 30, width = -10, x1 = 0).
