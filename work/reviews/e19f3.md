## Findings

Each finding is a checkbox. `must-fix` blocks `make review-pass` until a decompiler ticks it off
(with the commit that fixes it); `should` and `note` do not block.

- [x] must-fix src/E19F3.C:17-18: the header says 082C:05DD passes `extra1=2, extra2=0`, but that call has
  two paths. Path A: `[8102]` is 0 or 1 and `si` is 2 (082C:0569..0577, then 058F..05CE, after the lcall at
  082C:0587) pushes `extra2=2` (082C:058F) then `extra1=4` (the `mov ax,4` at 082C:0593 reaches the push at 05CE).
  Path B: `[8102]` is 2 and `si` is 0 (082C:059D..05A1, then 05B5..05CB) pushes `extra2=0`, `extra1=2`. Both
  paths push x1=y1=x2=y2=0, width=40, height=200 at 05CE..05DC. The header should give both values with their
  conditions (or say the extras are 2,0 or 4,2 at 082C:05DD). Evidence: disassembly of 082C:0569..05E2.
  Fixed (f8d0952): the header now gives both paths, path A with [8102] 0 or 1 and si 2 passing extra1=4,
  extra2=2 (082C:058F, 0593..05CE), path B with [8102] 2 and si 0 passing extra1=2, extra2=0 (082C:05C8..05CE).

## Summary

The unit is understandable from its source alone. `ClipRect` names what the bytes do (clip the top and left
origins, cap the size, return early for an origin at or past 40 columns), and the parameter names x1, y1, x2,
y2, width, height are backed by the caller values and by the region table in src/E1A29.C. The header's unit
paragraph is an inference that fits the bytes. The one must-fix is the call-site paragraph: it gives one set of
extras for 082C:05DD, which has two paths, so the header's evidence is wrong for half of them. The names
extra1 and extra2 are honest placeholders (their roles are unknown), and gFar8052 is an address name that
needs a declaration comment saying it is set at run time. With the header fixed, the review should pass.
