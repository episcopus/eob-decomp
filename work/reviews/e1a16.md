## Findings

- [ ] should src/E1A16.C:2: the header calls port 3DAh "the CRTC status register". 3DAh is the VGA Input Status Register 1 (the CRTC index port is 3D4h), as src/E1DE4.ASM:2 and :6 already say; use "Input Status Register 1" and "bit 3 (vertical retrace)" so the two files agree. The behaviour claim itself (f1DE4_000D polls 3DAh bit 3, so the unit is a frame delay) is right: E1DE4.ASM reads `in al,dx` / `test al,8` in loops.
- [ ] should src/E1A16.C:7: `gFE6C` has no description. Evidence on the bytes of EOB.EXE (file offsets minus the 0x2800 header): the only three references to ds:FE6C in the image are 1A16:0014 (`push [FE6C]; call far 1DE4:000D`, file 0x1c972), `xor ax,ax; mov [FE6C],ax` at 1A65:0023 (file 0x1ce73) and `mov word [FE6C],1` at 1A65:00CC (file 0x1cf1c; all in the 1A65 routine that measures retrace sample counts, per the E1DE4.ASM comment at 1DE4:0000). So it is a 0 or 1 value chosen at startup, and f1DE4_000D tests only whether it equals 1 (which retrace edge order to wait for). A one line comment saying "0 or 1, set by 1A65 (retrace measurement), selects the edge order of f1DE4_000D" would help. `int` is fine for the type (pushed as a word, compared as a byte). The name stays a placeholder; no must-fix.
- [ ] note `WaitFrames(int n)`: `while (n--)` is the matched form, so n <= 0 waits 0 times only for 0; a negative n would loop about 65000 times. Callers (14EF:0078, overlays 0/1/6, 0EF3:2A53, 0EF3:2EBC via WaitFrame) were not checked for how n is computed; not a finding for this unit.
- [ ] note The names WaitFrames and WaitFrame are supported by the single callee (a retrace wait per iteration) and the `n` loop; "frame" assumes one retrace per displayed frame, true of VGA mode 13h (not checked here, [H]).

## Summary

The unit is two tiny functions, understandable from its source alone: WaitFrames loops n times calling the retrace wait with the global mode flag, and WaitFrame is WaitFrames(1). The names are reasonable and backed by the callee's 3DAh bit 3 polling. Two "should" items: the header misnames port 3DAh, and `gFE6C` deserves a comment (it is 0 or 1, set by the 1A65 retrace measurement). No must-fix.
